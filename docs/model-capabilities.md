# 模型上下文与输出配置

后台“模型与定价”按模型分别配置上下文窗口和最大输出，可输入 `200K`、`1M`、`128K` 等十进制单位。发布后实际保存为整数 Tokens。

## 配置规则

- `0 < 最大输出 <= 上下文窗口 <= 10,000,000`。这是本服务的配置边界，不代表任何供应商都支持该额度。
- 以实际供应商、实际路由和账户支持的能力为准。仅有模型名称、成功的短文本请求或 `/models` 列表，不能证明长上下文、最大输出或图片能力。
- 同一映射配置 fallback 时，每个目标都必须支持该映射公布的能力；否则应降低共同额度或拆分映射。
- 不根据模糊模型家族名称推断能力。升级生产配置前，应保存供应商能力说明及真实长请求验收记录。

## 请求与计费

模型列表公布的输出限制与请求计费预留使用同一模型配置。预留通过后，网关将同一输出上限传给上游。移除历史统一 32K 截断，不改变最终按实际用量结算的规则。

较高的最大输出也意味着较高的预留额度。卡密余额或日/月额度不足时，请求在调用上游前被拒绝，不能只按预期短回答成本判断可用余额。管理员应根据产品需求设置合理输出上限，不应一律填满供应商最大值。

## 2026-09-21 核查

生产六个 Claude 别名当前为 200,000 上下文 / 8,192 最大输出。供应商 `/v1/models` 只提供名称与创建时间，没有能力字段；本次代码修复不把这些值自动改为 1M。历史发布脚本不应再用统一默认值覆盖已有模型配置。
