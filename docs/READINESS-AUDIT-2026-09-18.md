## 发布前结论

本轮是本地候选变更，不是“全部功能已完成”的验收证明。尚未部署这些变更，不建议让客户开始正式验收。没有使用客户验收卡，没有把模拟 CLI 或网关协议测试当成真实 IDE 验收。

## 本地补齐

- 后台新增受管理员鉴权保护的 GET/POST `/api/v1/admin/commercial-config`。支持新增/更新分组、模型映射、价格表头，以及追加价格版本。
- 发布要求当前配置 revision 和变更原因。拒绝旧 revision、含糊模型别名、跨组专属上游、价格版本覆盖、追溯定价和非法数值。
- 配置与审计在一次候选快照中持久化；写入失败不修改内存配置。读取接口不返回卡密或上游密钥。
- 由于结算仍读取当前分组/模型倍率，存在 held reservation 或 pending settlement 时拒绝发布。当前是空闲期发布，不是连续负载下无停顿热发布。
- 管理端分组和模型页面接入配置发布。当前为校验后的 JSON 配置编辑器，不等同于完整可视化表单。
- Kiro 配额展示按卡的实际总积分/已用积分计算，关闭超额使用展示。不同档位不再统一显示分组虚拟上限。
- 激活流程在关闭 IDE 前校验卡密，认证预检不写本地凭据；认证接口本身仍可能产生云端激活/设备绑定，不能承诺取消 IDE 关闭就撤销云端激活。
- 状态窗口增加“启动 Kiro”，复用本地会话鉴权、进程停止检查、快照/补丁完整性检查和 HTTPS CA 校验。
- 新建会话将有效网关 CA 复制到托管会话目录供后续启动使用，不依赖原始证书文件一直留在安装包目录。没有关闭 TLS 校验。

## 上线阻塞项

- TOTP 2FA 尚未实现；部署当前是单进程持久化账本，不能声称有数据库部署级 RLS。
- 外部搜索/专用补全的生产配置和真实上游能力尚未完整验收。
- 真实 Kiro 的模型列表、对话、工具调用、刷新令牌、关闭后重启、余额耗尽等完整交互尚未验收。
- 原有 Kiro 快捷方式不保证注入启动环境。当前只能声称通过本客户端启动入口设置所需环境。
- 接管失败会保留恢复记录，尚不能声称所有失败阶段都自动回滚凭据和云端设备绑定。
- 自包含客户端交付仍需检查 Node 等本机依赖；目前编译 Debug 和最终用户可分发包不是同一项验收。
- 本轮新增接口与前端尚未部署，尚未在生产验证持久化重启、配置发布以及客户卡隔离。

部署前必须通过本轮 Rust 回归、严格 Clippy、管理端构建和本地桥接/浏览器回归；随后备份账本、镜像及静态资源，用独立临时测试卡验收生产，不消耗客户卡。
