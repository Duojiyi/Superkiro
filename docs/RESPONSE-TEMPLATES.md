# 固定代码模板服务

管理台的「响应模板」页面可按当前用户消息的完整匹配或包含匹配，配置同一规则下不同模型的 HTML 文件内容、相对文件路径、提示文本和固定服务费。

## 配置

1. 新建规则，填写匹配方式与文本。按列表顺序检查启用规则；匹配文本和所选模型都命中才使用对应变体。
2. 给每个模型添加独立变体。同一规则不能重复配置相同模型 ID。未配置的模型继续正常上游流程。
3. 文件路径使用工作区相对路径，例如 `index.html`；不得使用绝对路径、目录穿越或 Windows 保留设备名。
4. 填写完整 HTML 代码。单个变体最多 256 KiB，所有规则序列化后最多 2 MiB。管理台不会执行或 iframe 预览代码。
5. 单次服务费为 0–1000 积分，最多六位小数。它是固定积分价，不叠加模型倍率，也不是 token 价格。
6. 核对内容与价格后启用规则，填写发布原因并发布。版本冲突须刷新核对；网络不确定时先读取服务器确认，不能盲目重发。

默认没有启用的规则。页面示例保持禁用、价格为零，不会自动对真实用户收费。

## 客户端与计费

- 客户端必须声明兼容文件工具：`fsWrite(path,text)`、`Write(file_path,content)`、`write_file(path,content)` 或 `writeFile(path,content)`。额外必填参数或无法验证的 schema 会免费拒绝。
- 响应明确声明为固定模板服务，非模型实时生成。服务器只发送写文件指令，不会声称已在客户端创建文件。
- 服务费按写入指令下发收取一次，扣费、Usage 和恢复回执原子持久化。文件工具报错不自动退款；可使用已有补偿流程核实处理。
- 模板不请求上游，上游成本和 token 用量均为零。用户余额、卡状态、模型权限、额度与并发限制仍生效。
- 24 小时内相同请求 ID 的兼容重试可恢复原指令和工具 ID，不再次扣费。恢复须使用原卡、会话、模型和兼容工具。
- 模板回执免费。已过期或被清理的模板工具 ID、跨会话回执、混合工具结果明确拒绝，不落入收费上游。
- 携带回执的新指令不会隐式执行，需另发一条消息。写入成功仅根据客户端回执报告，服务器无法独立验证本地文件。
- 回执存储受条数和序列化字节双重限制；达到容量时新模板请求免费拒绝，不驱逐有效恢复记录。
- 固定模板历史去重记录永久保留，最多 65,536 个 ID 或 4 MiB 序列化数据。达到任一上限时免费拒绝新模板下发，普通模型请求不受容量影响；应升级存储后再扩容，禁止清空历史记录绕过限制。

## API 与验证

`GET /api/v1/admin/response-templates` 读取配置；`POST` 全量发布，字段为 `expected_revision`、`reason`、`rules`。使用现有管理认证及浏览器 CSRF 防护。

回归入口：

```sh
cargo test -p billing --lib response_template
cargo test -p gateway --test response_templates_test
npm --prefix apps/admin-ui test
npm --prefix apps/admin-ui run test:browser
```

发布必须使用已通过 CI 的 main 提交，并执行既有 stage → promote 流程。上线默认保持规则关闭，正式匹配文本、模型代码和收费金额应由管理员明确发布。


## 首次升级预检

旧快照尚无模板历史迁移完成标志时，即使模板关闭，首次加载也需要读取并校验快照引用的全部历史归档。归档缺失或校验失败将拒绝加载，不能直接 promote。

1. 备份账本快照和归档；核对所有归档回执引用的文件在部署配置的归档路径下可读。若归档已转离线存储，先按原文件名与相对位置恢复到该路径，保留原始内容。
2. 在 stage 使用生产格式快照、完整归档及所需密钥验证首次加载；不得用空账本替代此项检查。
3. 确认迁移后的状态已正常持久化，再重启一次，验证账本和永久模板去重历史均可恢复，然后才允许 promote。
4. 不得删除归档回执、清空去重历史或手工伪造 `template_invocations_complete` 标志绕过校验。迁移失败时保持旧版本在线，补齐归档后重新 stage。
