# Kiro IP TLS 与桌面状态修复（2026-09-19）

## 根因与证据

Kiro 1.1.14 有多层代理：Agent 扩展中的打包代码，以及 `node_modules.asar` 中的核心 `https-proxy-agent`。
两处均可能在 TLS 隧道升级时移除 `host`，且 IP 地址不填入 SNI，导致证书身份检查使用错误主机名。
因此只修扩展内的一处字面量不足以修好 IDE。

`test_kiro_core_proxy.py` 用 Kiro 自带 Electron 的 Node 模式加载真实核心模块，不打开 IDE。
已复现原始 `ERR_TLS_CERT_ALTNAME_INVALID`；网关定向绕过代理后，实际 `createHttpPatch` override 路径 HTTPS 200。
独立测试卡的账号用量与非空模型列表查询通过；测试卡已禁用。没有激活、绑定或消费客户卡密。
错误 TLS 身份仍被拒绝。未设置 `rejectUnauthorized=false`，未关闭证书验证。
证据：`.acceptance/kiro-core-proxy-result.json`。

## 修复

- `http.noProxy` 仅添加网关主机，保留已有例外和其他代理设置；启动时合并 `NO_PROXY` 与 `no_proxy`。
- 旧接管快照在新增配置之前先保存可回滚状态；重复接管不重复添加例外；回滚保留迁移前用户配置。
- 扩展内 HTTP 与 SOCKS 隧道路径均保留 IP host。
- 重新启动已接管会话也执行补丁和设置迁移。仍要求 IDE 停止后才能修改；不强制关闭未保存工作。
- 诊断实际检查补丁哈希及恢复备份，新增直连规则检查与真实 IDE 验收警告。

## 参考 VSIX

只读检查 `references/kiroapi-8.0.1.vsix`（kiroapi 8.0.1）：其本地服务监听 127.0.0.1，分别配置 CPS、KRS 和通用 endpoint，并处理管理请求误路由。
它没有通过关闭 TLS 校验处理此问题。本次没有执行该插件、导入其密钥或复制其实现；不额外引入一套本地代理。
当前项目已配置三类 endpoint，本次解决遗漏的核心代理路径。

## 桌面

去除带有静态文字的整窗截图背景，改成可响应式排版的真实组件。统一顶栏、间距、按钮、返回与错误提示。
验证成功先显示授权，手动接管前不修改 IDE。接管后保留授权详情并再次只读刷新；公开授权元数据仅存在当前标签页 sessionStorage，不存卡密。
显示查询时间，明确积分为查询时快照，而非实时余额。清理虚构加速状态与无数据统计。
提示消息不覆盖按钮；常见进程/TLS 错误中文化。诊断与设置窗口尺寸同步调整。
