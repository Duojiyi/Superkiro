# 智能复杂度分流

服务端按任务语义选择已有模型映射中的渠道，不改变客户端、对外模型名或客户计费单价。后台入口：**智能分流**。

## 配置和启用

1. 在渠道管理中配置分类器渠道及可用密钥。支持 OpenAI 兼容 Chat Completions 或 Anthropic Messages 的非流式 JSON 文本响应。分类器必须有权访问目标模型所属分组。
2. 在智能分流中选择分类器渠道，填写真实模型 ID、超时、每日调用量和费用上限，以及分类模型的输入/输出价格。价格按人民币每百万 token 输入；不是客户积分价格，也不能假设供应商免费。
3. 为已有模型映射分别选择简单和复杂任务的有序渠道链。仅能选择该模型已有的主渠道及备用渠道，沿用各自的上游模型 ID。复杂链不要包含不适合复杂任务的低能力渠道。
4. 保存配置后，使用不含敏感信息的样例预览。预览不生成答案，但启用中的策略会调用分类器并消耗同一分类预算；关闭策略的预览不产生外呼。
5. 先使用“观察”：记录建议和实际服务渠道，实际候选顺序不变；核对代表性任务后改为“执行”。改回“关闭”停止新请求分类。已经开始的请求保留既有决策以防重试改变路线。

## 判断规则

- 响应模板先匹配；命中模板不会调用分类器。
- 图片、文档和高推理要求走复杂链，不向分类器发送附件。
- 工具结果和明确的“继续”等续接请求优先复用同一用户、会话、模型映射下的最近有效决策；已知实际成功渠道优先。策略版本变化或没有可复用状态时走保守链。
- 只把明确独立、低风险的问候、短改写、短翻译和一般问题视为简单。编码、调试、架构、多步骤工作和不确定情况按复杂或未知处理。
- 长上下文或上下文截断时不猜测任务难度，使用复杂链。这是刻意保守的第一版行为，不会为压缩上下文额外调用模型。
- 分类器只能返回受校验的枚举标签，不能指定渠道、URL、密钥或模型。最终渠道仍须通过现有权限和能力筛选，保存建议前就与当前合法候选取交集，不会重新加入被排除的渠道。停用某个备用渠道不影响剩余合法候选；观察建议链为空也不阻断原回答链。

## 时延、成本与故障

- 分类调用独立限制为 8 个并发；超时可设 200–5000 毫秒，建议从 1500 毫秒开始，不重试分类。
- 连续 3 次分类失败触发 60 秒进程内熔断；超时、错误 JSON、忙碌、不可用、预算耗尽或判断不明都使用复杂链。
- 开始外呼前持久化决策和保守费用预留。正常有效 usage 按实际 token 调整；超时或无法确认 usage 时保留预估费用，避免不确定请求重复花费。
- 每日预算按 UTC 日期计算，包含管理员预览。费用是根据配置价格计算的估计，不是供应商账单对账；错误价格会影响控制效果。
- 相同 invocation 和请求内容复用已保存决策，重启后也不重新分类。不允许同一 invocation 更换请求内容。
- 持久化失败时拒绝开始未落盘的分类；不可静默外呼后丢失计费和幂等状态。
- 决策元数据保留 7 天，最多 20000 条；容量耗尽时停止新增分类和明细记录，按当前已确定的合法渠道继续答复（新任务走复杂链，既有续接保留合法路由），观察模式保持原路由；不会驱逐仍在幂等保留期的记录，也不会放过其他持久化故障。高吞吐场景需先评估此上限。

## 隐私与可观测性

分类器会接收当前用户文本和最多 4 条近期用户/助手文本，并受总输入字符上限控制。不发送系统提示、工具定义、工具结果、图片/文档内容、思考签名和访问密钥。用户文本本身仍可能包含敏感信息，因此应先确认分类器服务商的数据处理政策，再主动启用。

持久化及后台记录只包含任务范围哈希、请求哈希、分类标签、原因、建议渠道、实际服务渠道、耗时和分类费用，不保存分类输入文本。页面展示保留记录占用并在接近上限时提示，以及最近 50 条决策；预览以独立范围记录，不影响真实会话的续接选择。

## 运维回退

关闭策略是常规停用方式。不要删除仍有在途请求使用的渠道；原渠道被禁用或无权访问时不会被强行重新启用。发布采用原有候选构建、备份、就绪检查和失败回退流程。数据库新增字段有默认值，可读取启用前的快照；回退旧程序前应使用该发布事务对应的数据备份，不能假设旧程序可保留新版本路由状态。

本功能不要求重新打包或升级桌面客户端。
