# 桌面客户端错误反馈

用户界面不再提供诊断页面或诊断报告页面。操作错误在当前页面显示中文说明、稳定错误码、反馈编号，并可复制脱敏信息。恢复配置的入口无需卡密，不能因为授权失效而隐藏。

## 错误码

| 错误码 | 类别与处理方向 |
| --- | --- |
| SK-KIRO-001 | Kiro 版本不支持，升级至 1.1.14 或更高版本 |
| SK-AUTH-001 | 卡密或凭据无效 |
| SK-AUTH-002 | 授权过期 |
| SK-AUTH-003 | 授权被拒绝，核对授权及设备状态 |
| SK-AUTH-004 | 认证限流或暂时锁定 |
| SK-BIND-001 | 设备绑定不匹配 |
| SK-BIND-002 | 换绑冷却期，按返回等待秒数处理 |
| SK-BIND-003 | 换绑次数用尽，等待不会恢复次数 |
| SK-BIND-004 | 远端解绑成功、本地清理失败，只处理本地恢复，不重复解绑 |
| SK-NET-001 | 超时；写操作结果须先确认 |
| SK-NET-002 | 网络连接失败 |
| SK-NET-003 | TLS 或证书问题，禁止关闭证书校验绕过 |
| SK-CONNECT-001 | 连接前置检查失败 |
| SK-CONNECT-002 | 关闭 Kiro 失败 |
| SK-CONNECT-003 | 应用连接配置失败 |
| SK-CONNECT-004 | 准备或启动 Kiro 失败 |
| SK-RESTORE-001 | 本地还原失败，保留快照与备份 |
| SK-LOCAL-001 | 本机权限不足 |
| SK-LOCAL-002 | 操作仍在进行，先等待状态确认 |
| SK-LOCAL-003 | 系统凭据服务失败 |
| SK-PREVIEW-001 | 浏览器预览，无桌面宿主，未执行操作 |
| SK-UNKNOWN-001 | 暂未分类的失败，不能据此断言具体根因 |

## 数据约定

宿主 IPC 失败返回 `code`、`feedback_id`、`stage`、`outcome`、`retry_after_seconds`、`occurred_at`。UI 只接收允许字段，消息由本地固定文案表生成，不呈现底层原始错误。暂未分类的错误使用兜底码，后续按实际案例增加分类，不将未知错误伪装成已知原因。

- `failed`：本次请求失败，不意味着所有副作用均已回滚。
- `partial`：远端成功但本地仍有恢复工作，不能整笔重试。
- `unknown`：结果未确认；宿主仍在执行时查询操作状态并禁止重复写入。若宿主已结束但云端结果仍不明，不自动重试云端操作，提示联系支持核对；纯本地还原仍应可用。

宿主跟踪的写操作在 `last-operation.json` 中保存最近操作的脱敏元数据及 `support_error`，返回给 UI 的反馈编号与保存记录一致。该文件只保存最近一次操作，不是长期日志库。内部检查能力保留，但不通过用户诊断页面展示。

复制信息仅包含错误码、反馈编号、时间、阶段、结果和通过格式校验的客户端/Kiro 版本。不包含卡密、令牌、网关地址、安装路径或原始日志。由前端等待超时生成的 `UI-` 编号不会自动写入宿主记录；操作最终失败后，界面使用宿主的反馈编号。

## 支持流程与边界

请用户复制反馈信息并说明触发动作。先看错误码与操作结果，再核对版本、发生时间和本机最新脱敏操作记录。不要要求公开上传凭据、快照或完整日志。

错误码定位的是故障类别，反馈编号标识的是一次本地错误。当前未建立本地反馈编号与云端请求日志的贯通关系，云端根因仍需结合对应时间段的脱敏服务端证据排查。分类单元测试及 UI 测试不替代 Windows/macOS 真机接管与还原验收。
