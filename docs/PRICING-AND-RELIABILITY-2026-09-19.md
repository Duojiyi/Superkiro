# 采购成本、积分与套餐建议（2026-09-19）

## 已核实的事实

- 上游 `/v1/models` 返回 12 个 ID（含日期别名），不是只有一个模型。
- 截图所列 6 个 ID 均通过独立短文本请求：Sonnet 4.6、Sonnet 5、Opus 4.6/4.7/4.8/5。
- 这证明这些 ID 在该上游可调用，不证明其底层模型身份，也不等同于完整 IDE、图像或工具能力验收。
- 原线上仅配置环境变量默认 Sonnet，没有持久化模型映射；因此只显示一个。
- 线上账本存在真实扣费。最近三笔用户卡请求扣除 0.163212、0.493568、0.185906 积分。内部单位为微积分，1 积分 = 1,000,000 微积分。
- 桌面原本显示验证卡密时的静态快照。新版本通过已存授权只读刷新用量，每 30 秒更新可见的已接管主页，显示六位小数及时间；查询失败明确保留旧快照。
- 原默认计费不是正式套餐：每百万 token 输入 15、输出 60、缓存写入 18.75、缓存读取 1.5 积分（另受现有配置倍率影响）。新增模型不能因此被解释为已经完成商业定价。
- 后台当前财务使用配置中的积分面值和采购成本估算，并不是实际订单现金利润。历史记录不应倒改来美化毛利。

## 你的采购成本

以下以“截图单价尚未乘分组倍率，充值 1 元得到 1 美元余额，使用时再乘 0.08”为前提。如果截图已经打折，不能再乘一次。

实际人民币成本 = 上游标价美元消耗 × 0.08。

这里不再乘美元兑人民币的银行汇率，因为你说的是供应商内部充值兑换比例，不是法币外汇兑换。

Opus 5（截图）：

| 项目 | 上游标价 / 百万 token | 实际成本人民币 / 百万 token |
|---|---:|---:|
| 非缓存输入 | $5 | ¥0.40 |
| 输出 | $25 | ¥2.00 |
| 缓存写入 5 分钟 | $6.25 | ¥0.50 |
| 缓存读取 | $0.50 | ¥0.04 |

只采用明确给出的 5 分钟缓存写入单价。其他 TTL、长上下文加价、特殊服务费应分别核对。其他 5 个模型的成本不能仅凭名称猜测。应以供应商账单和 token usage 交叉核对一次真实请求，确认 input 是否包含缓存，避免重计。

## 推荐的积分定义（提案，尚未发布）

建议统一定义：1 积分对应 ¥0.015 的模型采购预算。各模型按真实采购成本折算积分，不按请求次数一刀切。

消耗积分 = 本次模型采购成本人民币 / 0.015。

该采购预算只是内部计量基准，不是向用户承诺积分可提现。六位小数计费，展示精度不改变账本精度。

按上述 Opus 5 成本，每百万 token 的积分价格：输入 26.666667，输出 133.333333，缓存写入 33.333333，缓存读取 2.666667。不同模型单价不同，因此同样 token 数消耗不同积分。

例如未缓存输入 20,000 token、输出 2,000 token：成本 ¥0.012，消耗 0.8 积分。按 ¥49/1000 积分出售，对应分摊收入 ¥0.0392，模型成本口径毛利率约 69.39%。实际还要扣运营等成本。

## 套餐提案

| 套餐 | 售价 | 积分 | 全部用完的采购成本 | 模型成本口径毛利率 |
|---|---:|---:|---:|---:|
| 体验包 | ¥9.9 | 150 | ¥2.25 | 77.27% |
| 主推月包 | ¥49 | 1000 | ¥15 | 69.39% |
| 大额月包 | ¥89 | 2000 | ¥30 | 66.29% |
| 限时促销底线示例 | ¥39 | 1000 | ¥15 | 61.54% |

建议正常销售目标为 65%–75% 的模型成本口径毛利，留出故障重试、汇损、服务器、支付手续费、退款、客服、获客和税费空间。先小规模观察真实账单，再决定促销底价；不承诺固定净利润。若成本翻倍，¥49 包的这一毛利率降至 38.78%，须支持新价格版本而非静默扣更多分。

毛利率 =（收入 - 成本）/ 收入；加价率 =（售价 - 成本）/ 成本。成本乘 1.3 是加价 30%，毛利率只有 23.08%，不是毛利 30%。

若每包分摊额外运营成本为 O、支付费率为 f、目标贡献利润率为 g，则售价下限约为 (15+O)/(1-f-g)。获客成本、退款和税务口径应与会计定义一致。

## 与 Kiro 官方对标的边界

以你提供的 $20 / 1000 官方积分为比较基准，没有在本轮独立核实官网套餐。¥49 的现金门槛较低；但我们的 1000 积分与官方 1000 积分不是天然等价，不能宣称相同工作量或按标价比例计算“便宜几倍”。

正确比较方式：固定一组真实 IDE 任务（修改多文件、测试、重试、长上下文），对比成功完成任务的总费用、耗时与质量，并记录缓存命中、所有 agent 子请求和工具循环。

不建议无限量、不建议所有模型同价、不建议靠用户用不完积分来维持毛利。月包应明确有效期、并发、频率上限及不滚存规则；套餐变动需明确告知。

## 商业化上线前的计费要求

1. 采购账本按 CNY 写入已经折算后的价格（如 0.40/2.00/0.50/0.04），避免再被 USD 汇率 7.25 放大。
2. 销售价独立配置，不能把毛利倍率同时当成上游分组倍率。
3. 固定积分方案对应的后端字段单位是“每百万 token 的微积分”，不是普通积分；发布前有整数舍入测试。
4. 当前全局积分面值默认 ¥0.01，而 ¥49/1000 的实际成交面值为 ¥0.049。若不修正收入归因，后台毛利图表仍会失真。不同折扣订单最好分别记录已确认收入/赠送积分，不能只改一个面值就宣称现金利润准确。
5. 不修改旧账本；价格版本仅向未来生效。显示“预估采购成本/配置面值收入”，直到订单账款对齐。
6. 成功或部分交付按既有结算规则记录；无输出失败释放预占。自动重试仍可能在上游产生运营成本，不向用户把同一逻辑请求重复扣费。
7. 超时重试限定首个文字/推理/工具事件之前；认证、参数、无法解析的协议错误不盲重试。429 在未保留 Retry-After 前走既有冷却，不盲目连发。
8. 所有正式模型逐项确认采购单价和能力后才发布正式价目表。本轮新增目录用于测试，不能视作以上套餐已开售。
