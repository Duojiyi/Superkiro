# Superkiro 整改与独立复审

日期：2026-09-19。对象：当前未提交工作树，不是线上版本。原始审计 `2026-09-19-project-audit.md` 保留，不以本报告覆盖历史发现。

## 范围与方法

本轮实施修复，使用本地单元测试、临时目录、受控时钟、模拟 HTTP/IPC 与浏览器夹具验证。没有部署、推送 GitHub、登录生产、启动桌面应用或操作真实 Kiro。Rust 测试中的子进程是测试夹具，不是用户 IDE。

实施后，两位独立审查者分别阅读当前源码，不互相查看发现，也未读取原审计报告；主线程核实并回交修复后再复核。这是隔离交叉审计，不宣称严格科学实验意义的双盲或全项目无漏洞。后续两位审查者分别修复运维追加项，再交叉只读复核对方实现；最终停服契约、路径、清理及失败回滚四类检查通过。调账精度、焦点鉴权与可用余额另经独立静态复核，历史版本发布保护也由非实施者复核。

## 独立复审追加修复

- A1：管理界面焦点鉴权不卸载工作区；复查期间禁止交互，认证失效才清空，避免草稿无提示丢失。
- A2：调账补齐金额限制和明确拒绝分支；未知结果继续锁定原始意图，不能换键绕过。
- A3：桌面区分写请求尚未发送与已发送结果未知，避免等待一个根本不存在的操作终态。
- A4：用量接口新增 availableCredits，宿主透传，React 以真实可用余额为准，包含在途预留；null 不冒充零。
- A5：所有模型映射隐藏时返回空目录，不补回一个对话路由不接受的环境默认模型。
- B1：恢复默认使用容器 UID/GID 1000，可显式覆盖；0600 文件在提交前核对实际服务用户读写权限。
- B2：冷备份读取锚点所指的权威代际，允许镜像落后或缺失；恢复先落代际，最后发布锚点。
- A2 追加：调账按十进制字符串验证最多六位小数和微积分边界；旧零微积分意图仅在明确未提交的特定拒绝下解锁，未知结果继续保留原幂等键。
- 运维追加：冷备份/恢复直接核对实际容器状态，探测失败不再当作停机；仅清理冷备份根部成套文件，不递归破坏在线备份。
- 恢复追加：自定义 DATA_FILE 路径和文件名贯穿恢复；准备权威代际副本失败即中止。逐项检查回滚，失败不再误报成功，首次恢复记录原先缺失的文件状态。
- 发布追加：部署锁内核对历史不可变产物，阻止旧版本号换包；CI 分别执行两个 shell 脚本语法检查。

## 需求补齐

- 管理员环境配置式 TOTP：六位 SHA1、30 秒周期、时间窗、并发防重放及限速；非法配置不降级。前后端统一 totpCode / twoFactorEnabled / expiresAt（Unix 秒）。不等于可视化扫码开户、多管理员或找回流程。
- 管理请求 deadline、真实会话到期清理、返回页面再鉴权；匿名状态只渲染登录页。
- 财务设置通过既有版本化发布事务保存，采购成本、积分面值估算与实际现金收入分离；成本覆盖不足不宣称完整利润。
- 桌面常规登录页不展示网关地址，平台路径选择文案区分 Kiro.exe / Kiro.app，补齐加载、未知、失败状态和表单标签。
- 新增发布验收文档、备份服务及 timer 样例、离线回归。Python 是构建/运维工具，不是新桌面的运行时。

## 尚不能宣称完成

- 数据库部署级 RLS：当前是单进程加密文件快照，不存在已运行的数据库 RLS。应用层分组隔离不是替代品。
- 外部搜索与专用补全：已有库级能力不等于线上后端已配置及商业计费验收；不得以默认空结果或节流冒充可用。
- 实际付款收入、采购账单、退款及完整历史财务对账尚未接入。页面估算不是实收利润。
- 真实 Windows / Kiro 全流程、窗口拖动圆角、动效与 Pencil 逐像素一致性、Mac 左侧窗口按钮和退出行为需要实机验收。
- Mac 改名 bundle 的完整支持、Developer ID 签名/公证、Windows 商业签名、下载信誉未完成。本轮未运行 Mac 构建。
- 生产域名、上游全部 Key/模型授权、真实回复与恰好一次扣费、线上备份 timer、离机恢复未在本轮验证。
- Windows 跳过的 POSIX 文件归属测试仍需在 Linux 执行；不以 shell 语法检查替代真实恢复演练。备份/恢复面向现有容器部署，容器须保留且停止；非容器部署未提供停服验证方案。停服检查不等于跨进程维护锁，操作期间必须禁止启动/部署；故障注入覆盖可捕获的命令失败，不代表 SIGKILL 或断电演练通过。

用户实际验收通过之前不发布、不覆盖现有下载文件。以上边界不能被“测试通过”概括掉。
