# 桌面窗口与布局修整

## 修复范围

- 非交互顶部区域（品牌、标题栏空白、外侧顶部留白）通过宿主开始拖动；按钮、输入框和页面内容不触发拖动。Windows 双击标题区域切换最大化。
- 只在登录/主界面尺寸类别改变时请求调整窗口，切换主导航不重置用户尺寸；保持最大化状态。按当前显示器工作区与缩放夹取窗口尺寸、最小尺寸和位置，支持负坐标副屏。
- 原生透明背景配合 CSS 圆角；Mac 透明配置与 macos-private-api feature 对齐（仅直接分发，不适用于 Mac App Store）。
- 登录窗口 480×540；主窗口默认 620×820。压缩冗余间距与说明，保留小屏、长动态数据的内部滚动兜底。
- 登录输入框使用单层焦点样式；波形增加错峰高度变化，尊重 prefers-reduced-motion。
- 精简余额与连接说明，保留余额更新时间、非实时及用量时区；Windows 文件夹选择按钮与实际选择器一致。
- 限制少量数据时的图表柱宽，避免单日数据撑满整张图。

## 验证

- Vitest：63 项通过。
- desktop-host：21 项通过，1 项安装只读预检为默认忽略；本轮单独执行该预检通过。
- Clippy -D warnings、TypeScript/Vite 与 Windows Debug 构建通过。
- 默认窗口布局：19 个场景通过，包含完整 7 项诊断、报告和有数据用量；无页面滚动、横向溢出及控件裁切。
- 小窗口/错误/恢复状态：30 个组合通过，内容保留可访问的内部滚动。
- 浏览器状态截图回归通过；波形两次采样 transform 实际变化，reduced-motion 下没有动画。
- 原生 Debug 已启动。原生截图工具两次失败：SetIsBorderRequired failed: 不支持此接口 (0x80004002)。因此真实鼠标拖动、原生圆角及高 DPI 实机视觉验收仍未确认，不能用浏览器结果代替。
- 未执行真实卡密接管/IDE 对话，没有修改 Kiro 配置。未推送 GitHub 或更新公开桌面下载。
