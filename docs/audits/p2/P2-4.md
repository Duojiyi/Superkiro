## 审计 B：对抗性盲审 (Adversarial Blind Audit)

针对 4 类核心多租户虚拟化对抗场景编写独立系统级测试 `crates/gateway/tests/group_virtualization_test.rs`：

### 对抗场景 1：多租户套餐名与额度隔离对抗
- **测试**：`test_audit_b_group_virtual_plan_and_quota_isolation`
- **攻击**：构造 Pro+ 分组（限额 50,000）与 Enterprise 分组（限额 999,999，套餐名 `KIRO ULTRA ENTERPRISE`）。
- **实测结果**：不同卡密发起的 `/getUsageLimits` 请求被严格隔离，Pro+ 获得 50,000 与 `KIRO PRO+`，Enterprise 获得 999,999 与 `KIRO ULTRA ENTERPRISE`，零信息交叉泄漏。**PASS**。

### 对抗场景 2：模型分组可见性与排序越权渗透
- **测试**：`test_audit_b_model_visibility_and_sorting_per_group`
- **攻击**：Group A 中设置 `claude-sonnet-4.5` 为 `visible: false`；Group B 中设置 `visible: true`。验证 Group A 调用 `/ListAvailableModels` 时是否能偷窥到该模型。
- **实测结果**：Group A 返回的列表中 100% 不含被隐藏的模型；Group B 正常拉取全部模型并严格遵循 `sort_order` 排序。**PASS**。

### 对抗场景 3：分组级企业提示词注入与上游验证
- **测试**：`test_audit_b_system_prompt_prefix_injection`
- **流程**：为 Enterprise 分组注入 `SECURITY_GUARD: All code must be memory-safe and follow Rust idioms.` 前缀；通过真实的 `/generateAssistantResponse` 发起会话。
- **实测结果**：Mock 上游收到的真实请求体内，系统消息首部成功注入企业安全规则，且原用户提示词保持完整。**PASS**。

### 对抗场景 4：Shared vs Dedicated 上游隔离防穿透
- **测试**：`test_audit_b_provider_binding_mode_isolation_shared_vs_dedicated`
- **攻击**：
  1. 共享组（Shared）卡密试图访问专属上游（Dedicated Provider with `group_id = Some("grp-dedicated")`）；
  2. 专属组（Dedicated）卡密访问其绑定的专属上游；
  3. 专属组（Dedicated）卡密试图访问公共共享池上游。
- **实测结果**：
  - 共享组访问专属上游被立即阻断，返回 HTTP 403 `AccessDeniedException`，预留额度安全回滚；
  - 专属组访问专属上游正常获得 200 OK 并流式下发；
  - 跨租户上游资源 100% 物理级隔离。**PASS**。
