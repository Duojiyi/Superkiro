## 审计 B：对抗性盲审 (Adversarial Blind Audit)

在 `crates/billing/tests/quota_test.rs` 与 `crates/gateway/tests/guardrail_test.rs` 中编写系统级对抗测试用例：

### 对抗场景 1：单卡密并发打满与释放重试（公平使用防护）
- **测试**：`test_card_concurrency_quota_fair_use`
- **验证**：设定卡密 `max_concurrency = 2`。并发发起 3 个预留请求。
- **实测**：
  1. 请求 1、2 成功冻结预留，活跃并发计数达到 2；
  2. 请求 3 立即被拒：`Err(BillingError::ConcurrencyLimitExceeded { current: 2, max: 2 })`；
  3. 释放请求 1 后，活跃并发回落为 1；重发请求 3 顺利成功预留。
- **实测结果**：**PASS**。

### 对抗场景 2：日积分用量上限与跨天零点重置
- **测试**：`test_daily_credit_limit_and_midnight_rollover`
- **验证**：设定卡密每日上限 50 积分。Day 1 消耗 30 积分后，尝试再预留 27 积分（30 + 27 = 57 > 50）。
- **实测**：
  1. 准确被拒 `BillingError::DailyLimitExceeded`；
  2. 模拟时间前推 24 小时进入 Day 2，`get_daily_usage` 自动重置为 0；
  3. Day 2 重新发起 27 积分预留立即成功通过。
- **实测结果**：**PASS**。

### 对抗场景 3：月度滚动周期用量上限阻断
- **测试**：`test_monthly_credit_limit_enforcement`
- **验证**：设定月上限 100 积分。当月已结算 90 积分，新请求拟预留 27 积分（90 + 27 = 117 > 100）。
- **实测**：触发 `BillingError::MonthlyLimitExceeded { limit: 100M, current: 90M, needed: 27M }`，严密防护月度超额。**PASS**。

### 对抗场景 4：在线卡密动态调配与模板生成继承
- **测试**：`test_dynamic_quota_updates_and_template_propagation`
- **验证**：模板设定并发 4、日上限 20、月上限 200；卡密从模板派生后验证字段全部继承；在线调用 `update_card_quotas` 将并发提升至 8、日上限放宽至 50、移除月上限。
- **实测**：卡密即时生效，无须重新发卡。**PASS**。

### 对抗场景 5：全局容量护栏饱和与快速失败
- **测试**：`test_capacity_guardrail_fast_fail_and_raii_release`
- **验证**：设置最大全局并发 2。前 2 个请求获取许可证成功；第 3 个请求因容量打满秒级返回 `CapacitySaturated`；释放 1 个后第 3 个请求成功获取。
- **实测**：零阻塞、零线程挂起，RAII 释放可靠。**PASS**。

### 对抗场景 6：Kiro 原生端点 429 协议一致性核验
- **测试**：`test_gateway_capacity_saturation_fast_fail_response`, `test_gateway_card_concurrency_quota_rejection`, `test_gateway_daily_and_monthly_quota_rejection`
- **验证**：通过真实 HTTP Router 请求 `/generateAssistantResponse`：
  1. 容量饱和时返回：HTTP 429 + `x-amzn-errortype: ThrottlingException` + `Retry-After: 5` + `reason: CAPACITY_LIMIT_REACHED`；
  2. 卡密并发超额返回：HTTP 429 + `ThrottlingException` + `Retry-After: 2` + `reason: CONCURRENCY_LIMIT_EXCEEDED`；
  3. 日上限超额返回：HTTP 429 + `ThrottlingException` + `reason: DAILY_LIMIT_EXCEEDED`。
- **实测结果**：Kiro 原生 AWS SDK 完全识别，无异常报错，自适应重试标头健全。**PASS**。
