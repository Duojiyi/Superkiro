## 审计 B：对抗性盲审 (Adversarial Blind Audit)

针对 6 种对抗场景编写独立系统级测试 `crates/gateway/tests/revocation_test.rs`：

### 对抗场景 1：封号即时切断对抗（Token 仍具有未到期的 1h TTL）
- **测试**：`test_audit_b_ban_card_triggers_instant_revocation`
- **攻击**：构造持有 1 小时有效期的合法 Token v1，先访问 `/ListAvailableModels` 获得 200 OK；管理员在毫秒内触发 `ban_card`。
- **实测结果**：旧 Token 再次发起请求，立即被网关拦截返回 401 `AccessDeniedException`（[Banned]），且系统拒绝为该被封卡密签发任何新 Token。**PASS**。

### 对抗场景 2：冻结并解冻后旧 Token 窃用对抗（Freeze-Unfreeze Replay）
- **测试**：`test_audit_b_freeze_and_unfreeze_lifecycle_revocation`
- **攻击**：用户持有 Token v1，管理员临时冻结卡密（`token_version` 升至 2），随后管理员解冻恢复卡密状态为 `Active`。攻击者试图使用手中的 Token v1 绕过。
- **实测结果**：即便卡密已恢复 `Active`，网关检查发现 Token 的 `token_version=1` 与卡密实时的 `token_version=2` 不符，依然直接阻断并返回 401 `TokenRevokedException`；唯有以当前 v2 重新签发的 Token 才能访问。**PASS**。

### 对抗场景 3：设备超限换绑淘汰旧设备（Evicted Device Session Hijacking）
- **测试**：`test_audit_b_device_rebind_eviction_revokes_evicted_device`
- **攻击**：设备 Alpha 登录并持有 Token v1；随后设备 Beta 换绑成功并导致设备 Alpha 被淘汰踢出。设备 Alpha 仍试图用手头的 Token 发起对话与模型请求。
- **实测结果**：设备 Beta 换绑时自增 `token_version`，设备 Alpha 的请求瞬间被网关判处 401 `TokenRevokedException`，老设备会话立即瘫痪；设备 Beta 签发新 Token 顺畅通行。**PASS**。

### 对抗场景 4：设备指纹解除绑定（Explicit Unbind Revocation）
- **测试**：`test_audit_b_unbind_device_revokes_tokens`
- **攻击**：用户或管理员将特定设备从已绑定列表中解绑。
- **实测结果**：解绑触发 `token_version` 自增，该设备历史 Token 立即报 401 `TokenRevokedException` 彻底失效。**PASS**。

### 对抗场景 5：用户端/管理端"一键下线所有设备"（Global Logout）
- **测试**：`test_audit_b_explicit_revoke_tokens_logout`
- **攻击**：用户发现密码/卡密疑似泄露，触发全端登出（`revoke_tokens`）。
- **实测结果**：全端 Token 瞬间失效，阻断所有未过期会话。**PASS**。

### 对抗场景 6：公开端点免登录与私有端点无票拦截
- **测试**：`test_audit_b_public_endpoints_accessible_without_token`
- **实测结果**：`/oauth/token` 与 `/refreshToken` 在无 Authorization 头时均能返回 200 OK 结构；业务端点无 Token 立即返回 401 `MissingAuthenticationTokenException`。**PASS**。
