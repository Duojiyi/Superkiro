## 审计 B：对抗性盲审 (Adversarial Blind Audit)

在 `crates/billing/tests/` 与 `crates/gateway/tests/` 中实施 13 个独立对抗测试用例：

### 对抗场景 1：主密钥安全注入与 Debug 防泄密
- **测试**：`test_master_kek_injection_from_hex_and_random`、`test_master_kek_injection_from_env_and_file`
- **验证**：通过 hex 编码、环境变量与文件注入 KEK，验证错误长度校验与 `Debug` 格式化。
- **实测**：
  1. `format!("{:?}", kek)` 严格输出 `MasterKek([REDACTED])`，杜绝日志意外打印主密钥；
  2. 非法长度 hex 字符串精准拒绝（`InvalidKekLength`）；
  3. 环境变量与临时文件路径均能无损读取 32 字节主密钥。
- **实测结果**：**PASS**。

### 对抗场景 2：AES-256-GCM 密文篡改与跨 KEK 伪造攻击
- **测试**：`test_tampered_ciphertext_or_wrong_kek_fails`
- **验证**：使用 KEK-A 加密密文，分别尝试：(a) 用不同密钥 KEK-B 解密；(b) 篡改密文单个比特（第 0 字节从 a 改为 b）。
- **实测**：AES-256-GCM 认证标签验证均告失败，全部精确拦截并返回 `CryptoError::DecryptionError`，杜绝密文填充与延展攻击。
- **实测结果**：**PASS**。

### 对抗场景 3：主密钥平滑轮换与批量重封装
- **测试**：`test_master_kek_rotation_single_and_batch`
- **验证**：准备 2 个由 `old_kek` 加密的密钥，调用 `rotate_all_provider_keys` 轮换为 `new_kek`。
- **实测**：
  1. 批量轮换成功率 100%；
  2. 轮换后 `old_kek` 无法解密任何已轮换密文；
  3. `new_kek` 成功恢复全部原始 API 密钥明文。
- **实测结果**：**PASS**。

### 对抗场景 4：多租户作用域横向越权拦截
- **测试**：`test_tenant_context_scoping_card_isolation`、`test_tenant_context_group_and_model_filtering`
- **验证**：租户 `group-alpha` 尝试读取/操作 `group-beta` 的卡密与专有模型配置。
- **实测**：直接抛出 `TenantViolation::CrossTenantAccessForbidden`，模型列表自动过滤排除异构租户模型；系统管理员上下文（`system_admin`）可合法穿越多租户。
- **实测结果**：**PASS**。

### 对抗场景 5：登录爆破防御滑动窗口锁定与自动恢复
- **测试**：`test_login_brute_force_progressive_lockout`、`test_login_brute_force_window_expiry_resets_counter`
- **验证**：连续注入 3 次登录失败，验证锁定状态与剩余倒计时；验证超出滑动窗口（30s）后计数器自动重置。
- **实测**：
  1. 第 3 次失败精准触发锁定，后续调用均拦截并返回精确 `remaining_secs`；
  2. 锁定到期后重新开放尝试；
  3. 窗口超时后旧失败记录不累加，防止正常用户偶发错密被锁死。
- **实测结果**：**PASS**。

### 对抗场景 6：请求体大小、多图攻击与超长 Prompt 防护
- **测试**：`test_content_guardrail_prompt_and_image_limits`
- **验证**：构造畸形请求体：超长 Prompt（>10,000字）、过多图片（>5张）、单图超标（450KB）。
- **实测**：分别被 `PromptTooLong`、`TooManyImages` 与 `ImageTooLarge` 拦截，杜绝恶意 payload 耗尽内存。
- **实测结果**：**PASS**。

### 对抗场景 7：双端口网络监听与路由完全隔离
- **测试**：`test_dual_listener_router_isolation`
- **验证**：在 Kiro 门面调用 `/admin/cards`；在 Admin 端口调用 `/generateAssistantResponse`。
- **实测**：两类跨端口越权请求均直接返回 `404 Not Found`，证明网络与路由层物理隔离生效。
- **实测结果**：**PASS**。
