## 审计 A（规格盲审）
- 独立写下的验收标准：
  1. 是否覆盖 spec §16-4（工具帧结构、分片 JSON、CRC 校验）：必须包含完整 prelude、header、payload 与 message CRC 字段，以及 chunked tool input 和 stop=true。
  2. 是否解答 spec §16-7（看门狗超时时间与保活建议）：必须给出实际代码中的预警时间、断流超时时间及网关保活帧设计。
  3. 是否解答 spec §16-8（invocation-id 在重试中的稳定性）：必须明确在 AWS SDK 重试各 attempt 中是否一致。
  4. 是否解答 spec §16-9（点击停止行为）：必须明确客户端点停止时底层发生什么操作。
  5. 语料文件是否可供后续 `kiro-wire` 进行 round-trip 测试。
- 对照结果：
  1. §16-4 工具帧结构与分片 JSON 机制完整：PASS
  2. §16-7 看门狗超时 60s/300s 证实，20~25s 空 content 保活方案证实：PASS
  3. §16-8 invocation-id 稳定证实（SDK for 循环初始化生成）：PASS
  4. §16-9 客户端停止行为证实（Node ClientRequest.destroy() 无任何 RPC 报文）：PASS
