## 审计 A（规格盲审）
- 独立写下的验收标准：
  1. 监听本地 HTTPS 端口（自签证书可工作）；
  2. 任意路径入站请求均能忠实录制（方法、路径、所有请求头、完整二进制请求体）；
  3. 样本输出至 `docs/p0/samples/`，包含文本说明（元数据 + Hex Dump + Base64）与原始二进制文件；
  4. 支持配置 `--upstream` 转发到真实官方后端并双向录制官方响应。
- 对照结果：
  - 标准 1：PASS（`server.py` 使用 `ssl.SSLContext` 默认监听 8443 端口）
  - 标准 2：PASS（`read_body` 覆盖 `Content-Length` 与 `Transfer-Encoding: chunked`，二进制直读）
  - 标准 3：PASS（`prefix = f"{seq:04d}_{method}_{safe_path}"`，生成 `.txt` 与 `.req.bin`）
  - 标准 4：PASS（支持 `--upstream`，记录 `.res.bin` 与响应元数据）

## 审计 B（对抗盲审）
- 运行的测试与输出：
  - 执行 `test_stub.py`，输出 `ALL P0-1 TESTS PASSED SUCCESSFULLY`。
- 构造的反例输入与结果：
  - 反例 1：体中包含 `\0` 空字符的 payload（`b"PREFIX_\x00\x01\x02\x00\x00\xFF_MIDDLE_\x00_SUFFIX"`），验证文本处理不会截断或转义丢字节。测试通过。
  - 反例 2：2MB 大体量随机字节流，验证无中间缓存上限截断。测试通过。
  - 反例 3：URL 中包含特殊字符及多层子路径，验证 `sanitize_path` 能够安全映射为合法文件名而不抛出 IO 异常。
- 发现的问题：
  - 大于 64KB 的请求体若直接输出数十万行 Hex dump 到 `.txt` 会导致编辑器卡死。`server.py` 中增加了对展示用 Hex dump 的预览截断（前 4KB），并在文末显著提示完整字节参阅 `.req.bin`，既保障阅读体验又确保字节保真。
- 结论：PASS
