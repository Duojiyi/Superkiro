## 一、审计范围与契约定义 (Spec §5, §14.6)

1. **别名规范 (Model Aliases)**：
   - `ModelMap` 扩充 `aliases: Vec<String>`。
   - 暴露 `matches_model(&self, requested: &str) -> bool`，匹配标准标识与任意别名（例如客户端传入 `claude-3.7-sonnet` 可无缝匹配标准映射 `claude-3-7-sonnet`）。
   - 计费引擎（`reserve` 与 `settle`）透明兼容别名，计费乘数与费率卡版本解析自动寻址规范模型。

2. **降级链规范 (Fallback Chain)**：
   - `ModelMap` 扩充 `fallback_chain: Vec<FallbackTarget>`（包含 `provider_id` 与 `target_model`）。
   - 提供 `full_target_chain(&self) -> Vec<FallbackTarget>`，依次级联主目标上游与候选备选池。
   - 网关层治理调度器实现 `execute_stream_with_model_fallback`：遍历候选上游，主模型节点不可用（全部 Key 冷却或上游异常）时，自动无缝切换至下一候选备选模型。
   - 结算器（`BillingSettler`）自动绑定实际承载模型与上游渠道，确保真实成本与客户账单精准一致。

## 二、实现验证与代码修改清单

1. `crates/billing/src/group.rs`:
   - 定义 `FallbackTarget { provider_id: String, target_model: String }`。
   - `ModelMap` 增加 `aliases` 与 `fallback_chain` 字段。
   - 增加链式构建辅助方法：`with_alias`、`with_fallback`。
   - 实现 `matches_model` 与 `full_target_chain`。

2. `crates/billing/src/engine.rs`:
   - `reserve` 与 `settle` 采用 `matches_model` 进行模型映射匹配，彻底消除因客户端调用别名导致的乘数或费率卡失效问题。

3. `crates/gateway/src/provider/governance.rs`:
   - 实现 `ModelFallbackResult` 及 `execute_stream_with_model_fallback`。
   - 在上游调用层确保切换模型时自动同步修正 `ChatRequest.model`。

4. `crates/gateway/src/facade/conversation.rs`:
   - `GenerateAssistantResponseHandler` 引入 `fallback_pools: HashMap<String, ProviderKeyPool>` 及 `.with_fallback_pool(...)`。
   - 运行时根据租户分组的 `ModelMap` 动态组装降级候选节点序列。
   - 发生降级时由流式流守卫和结算器结算实际交付的模型与供应商。

5. `crates/gateway/tests/model_fallback_chain_test.rs`:
   - `test_model_alias_resolution`: 验证别名请求精准映射目标模型并交付。
   - `test_model_fallback_chain_on_upstream_failure`: 验证主上游 500 故障时，网关透明故障转移到备用供应商与模型并返回 200 流式输出。
   - `test_model_fallback_chain_all_exhausted`: 验证所有候选池全部耗尽时，安全返回 502 并全额回滚释放冻结额度，零泄露。
