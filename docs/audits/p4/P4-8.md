# P4-8 审计报告: 客户端白标（名称/图标/主题/官网配置驱动）

## 1. 任务概述
- **任务目标**: 支持客户端全套白标配置（品牌名称、Slug、副标题、图标、主题色、亮暗色模式、官网、文档与技术支持外链等），实现构建期、环境感知及服务端配置驱动：
  1. 客户端 `WhiteLabelConfig` 配置实体，支持编译期与运行期环境变量重载 (`KIRO_BRAND_*`)
  2. 支持本地原子化磁盘保存与加载 (`save_to_file` / `load_or_default`)
  3. 支持服务端动态协商下发 (`POST /client/negotiate`) 与本地合并 (`merge_with`)
  4. 提供公开免密品牌元数据接口 (`GET /client/brand`)，供前端 Web 门户与客户端直接拉取
- **极简原则 (Ponytail)**:
  - 复用标准库 `std::env`、`std::fs` 与 `serde_json`，零新增依赖
  - 单一数据模型双向驱动（客户端本地缓存 + 服务端下发覆盖）
  - 纯粹的原子写入确保断电与异常退出不破坏配置

## 2. 变更范围
- `crates/patch-engine/src/white_label.rs`: 白标配置实体、环境变量推导、文件持久化与合并
- `crates/patch-engine/src/lib.rs`: 导出 `WhiteLabelConfig`, `ThemeMode` 等类型
- `crates/gateway/src/facade/client.rs`: 扩展 `ClientNegotiateResponse` 下发白标配置，新增 `ClientBrandHandler` (`GET /client/brand`)
- `crates/gateway/src/facade/mod.rs`: 注册 `ClientBrandHandler` 并加入公开路由白名单
- `crates/patch-engine/tests/white_label_test.rs`: 客户端白标单元测试 (2/2 passed)
- `crates/gateway/tests/white_label_test.rs`: 服务端白标与公开路由集成测试 (3/3 passed)
