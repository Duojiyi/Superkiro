# P4-5 审计报告: 发卡平台对接 API / Webhook (库存拉取 + 核销回调)

## 1. 任务概述
- **任务目标**: 实现发卡平台标准的对接协议：
  1. 库存拉取 API (`GET /api/v1/cards/inventory`)
  2. 订单级幂等拉取/出卡 API (`POST /api/v1/cards/pull`)
  3. 核销回调 API (`POST /api/v1/cards/redeem`) 支持卡密校验、激活、设备换绑与充值
- **极简原则 (Ponytail)**:
  - 复用 `crates/billing` 核心领域实体 (`Card`, `CardTemplate`, `TopupCode`, `LedgerEntry`)
  - 无需第三方复杂发卡平台 SDK，基于标准的 JSON 结构与 Axum 路由
  - 幂等性通过基于 `order_id` 的记录实现，防止发卡平台重复扣库存/重复出卡

## 2. 变更范围
- `crates/billing/src/card_platform.rs`: 发卡平台管理服务及请求/响应数据结构 (`CardPlatformManager`, `CardInventory`, `PullCardsRequest`, `RedeemCallbackRequest`)
- `crates/billing/src/engine.rs`: 扩展 `list_all_cards` 和 `redeem_topup` 支持
- `crates/billing/src/lib.rs`: 导出发卡模块类型
- `crates/gateway/src/facade/card_platform.rs`: Axum HTTP 路由与处理函数
- `crates/gateway/src/facade/mod.rs`: 注册卡密平台 Facade 路由
- `crates/gateway/tests/card_platform_test.rs`: 包含库存、出卡幂等性、卡密核销激活与充值续费的端到端测试

## 3. 测试验证
- `cargo test --test card_platform_test` 全部通过 (4/4 passed)
- 覆盖率验证：
  - `test_card_platform_inventory_query`: 测试各模板未激活/已激活库存统计
  - `test_card_platform_pull_cards_idempotency`: 验证重复拉取订单返回相同的卡号卡密，不重复消耗库存
  - `test_card_platform_redeem_verify_and_activate`: 验证校验与激活状态流转
  - `test_card_platform_redeem_topup`: 验证叠加卡余额与额度核销

## 4. 结论
- P4-5 通过审计，满足发卡平台全套标准规范对接要求。
