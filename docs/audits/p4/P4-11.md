## 一、技术与经济学评估报告 (Technical & Economic Evaluation)

### 1. 自动补全 (FIM / GenerateCompletions) 特征分析
在 Kiro IDE 中，Tab 自动补全由 `CodeWhispererRuntimeClient` 发起，具有以下三个显著技术特征：
1. **高频脉冲触发 (High Frequency & Burstiness)**：
   - 每次光标移动与击键暂停（debounce 约 100~300ms）即向网关发起单次 RPC 请求。
   - 正常编写代码时单用户可产生 20~50 req/min，是主对话交互频次的 50~100 倍。
2. **极严苛的延迟预算 (Strict Latency Budget)**：
   - IDE 内联灰色幽灵字符补全要求首字符到达时间 (TTFT) **< 200ms**。
   - 商业上游前沿大模型（Claude 3.7 Sonnet / GPT-4o）的 HTTP 往返 + TTFT 通常在 **600ms ~ 1500ms**。若将补全直接转发至主模型，用户键盘打字体验将严重卡顿，甚至在建议返回前用户已键入新字符而导致建议直接作废。
3. **成本穿透与限流挤占 (Credit Depletion & Rate Limit Starvation)**：
   - 每次补全上下文均携带 `leftFileContent` 与 `rightFileContent`（常见数百至上千 token）。
   - 若转发至收费商业 API，单张卡密额度会在数十分钟打字内被完全耗尽，且会严重占用租户供应商的并发与 TPM 配额，导致主对话流遭遇 429 限流。

### 2. 结论与工程决策 (Architectural Decision)
1. **默认策略（基线推荐）**：
   - 遵循 Spec §2.5 与 P0-7 决议：客户端注入 `"kiroAgent.enableTabAutocomplete": false`。
   - 若用户在 VSCode 设置中手动开启，网关默认处于 `Throttled` 模式，返回官方规范定义的 **HTTP 429** 与 `{"__type": "ThrottlingException", "reason": "MONTHLY_REQUEST_COUNT"}`。
   - 效果：Kiro 原生 UI 显示静默友好提示，彻底杜绝隐式 token 偷跑与意外扣费。
2. **可选冒充与外接高速补全模型 (Configurable Extensibility)**：
   - 提供 `AutocompleteMode::Empty`：返回 HTTP 200 `{"completions": []}`，实现完全静音零干扰的 no-op。
   - 提供 `AutocompleteMode::Forward`：当租户/管理员明确配置了专用低延迟代码补全源（如本地部署的 Ollama / vLLM DeepSeek-Coder 或高速 Qwen-2.5-Coder 节点）时，网关将 FIM 上下文包装转发并组装为 CodeWhisperer 标准结构，满足专业补全需求。

## 二、代码修改与实现清单

1. `crates/gateway/src/facade/completions.rs`:
   - 引入 `AutocompleteMode` 枚举（`Throttled`, `Empty`, `Forward`）。
   - 引入 `CompletionConfig` 结构体（`mode`, `provider_url`, `api_key`, `model`, `max_tokens`, `timeout_ms`）。
   - 改造 `GenerateCompletionsHandler`：
     - 支持 `with_mode` 与 `with_config`。
     - `Throttled`：严格返回 HTTP 429 + `x-amzn-errortype: ThrottlingException` + `reason: "MONTHLY_REQUEST_COUNT"`。
     - `Empty`：返回 HTTP 200 + `{"completions": []}`。
     - `Forward`：解析 `fileContext`（提取 `leftFileContent` / `rightFileContent` / `filename`），构造 FIM 提示词并发起非流式轻量补全调用，提取生成内容后封装为 `{ "completions": [ { "content": "...", "score": 1.0 } ] }`；上游故障或超时自动兜底空数组，永不阻塞 IDE。
2. `crates/gateway/src/facade/mod.rs`:
   - 注册 `GenerateCompletionsHandler::default()`。
3. `crates/gateway/tests/autocomplete_test.rs`:
   - `test_autocomplete_throttled_default_mode`: 验证默认 429 降级及 AWS 错误头规范。
   - `test_autocomplete_empty_silent_mode`: 验证 200 静默空补全响应。
   - `test_autocomplete_forwarding_mode`: 验证 FIM 转发与代码补全结构装配。
   - `test_autocomplete_forwarding_upstream_error_graceful_fallback`: 验证上游异常时网关安全降级为空列表，不抛出崩溃。
