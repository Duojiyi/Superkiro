## 审计 B：对抗性盲审 (Adversarial Blind Audit)

针对端到端全链路真实通信场景构造多重对抗与极端异常输入：

### 对抗场景 1：全链路真实 WireMock 对话流式推送与精细账本结算
- **测试**：`test_e2e_conversation_pipeline_with_provider_and_billing_settlement`
- **流程**：
  1. 构造 Anthropic 真实上游 SSE 流式报文（含 `message_start` 150 输入 token、文本 delta、`message_delta` 40 输出 token、`message_stop`）；
  2. 客户端携带合法 JWT 鉴权向 `/generateAssistantResponse` 发起调用；
  3. 网关原子冻结预留额度，成功发起上游代理；
  4. 二进制流实时下发，客户端利用 `EventStreamDecoder` 逐字节还原出完整文本 `"Hello world from BYOK!"`；
  5. 流式结束触发 `BillingSettler::settle`，账本精准计费扣除 40 output + 150 input 对应微积分，冻结额度归零，卡密余额精确扣减。
- **实测结果**：**PASS**。

### 对抗场景 2：SDK 瞬时重试防双扣（幂等缓存拦截）
- **测试**：`test_e2e_conversation_pipeline_with_provider_and_billing_settlement`（后半段）
- **攻击**：使用完全相同的 `amz-sdk-invocation-id` 再次打入网关。
- **实测结果**：网关短路返回缓存完成帧（`idempotent replay`），不再发起上游请求，卡密已用额度 `credit_used` 严格不变，杜绝双重扣费。**PASS**。

### 对抗场景 3：意图分类器本地零成本拦截优化
- **测试**：`test_e2e_intent_classifier_interception_optimization`
- **场景**：Kiro IDE 在每轮对话前发起内部意图分类请求（`"You are an intent classifier..."`）。
- **实测结果**：网关在读取请求体后毫秒级识别签名，直接在本地以 EventStream 格式返回概率分发 JSON（`{"chat":0,"do":0.95,"spec":0.05}`），不发起上游 LLM 调用，不扣减用户卡密积分，每轮对话节省 1 次 RTT 与 ~1s 延迟。**PASS**。

### 对抗场景 4：卡密欠费 / 零余额即时拒绝
- **测试**：`test_e2e_insufficient_credit_rejection`
- **攻击**：使用 0 余额的卡密发起对话请求。
- **实测结果**：网关在预留阶段立即拦截，返回 HTTP 402 `PAYMENT_REQUIRED` + `{"__type": "InsufficientCreditException"}` 结构化报文，杜绝任何白嫖与透支。**PASS**。
