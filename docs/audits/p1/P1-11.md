## 审计 B：对抗性盲审 (Adversarial Blind Audit)

基于极端高并发、恶意双扣攻击、孤儿泄漏与余额击穿等对抗场景进行全面攻击检验：

### 对抗场景 1：5 线程极端并发冲撞击穿余额攻击
- **测试**：`test_audit_b_concurrent_5_requests_anti_puncture`
- **攻击**：卡密余额仅剩 810,000 微积分（只够支付 3 次预留），同时启动 5 个并发线程同时打向该卡密发起预留争抢。
- **实测结果**：
  - 严格仅有 3 个请求成功预留（冻结 810,000 微积分）；
  - 其余 2 个请求原子性被拒（抛出 `CardError::InsufficientCredit`）；
  - 可用余额为 0，**绝未击穿为负数**（Anti-Overdraft 成立）。**PASS**。

### 对抗场景 2：重放双扣攻击实测（同一 `invocation_id` 多次结算）
- **测试**：`test_audit_b_idempotent_billing_prevents_double_charge`
- **攻击**：故意使用已结算的同一个 `invocation_id` 发起二次结算请求。
- **实测结果**：二次结算被系统立即拦截并返回 `BillingError::DuplicateInvocation`；账本条目数严格保持为 1，卡密扣除金额未翻倍。**PASS**。

### 对抗场景 3：异常断连导致孤儿预留超期回收实测
- **测试**：`test_audit_b_orphan_reservation_reclaimed_by_janitor`
- **攻击**：请求成功预留 270,000 微积分后，上游未完成且未释放连接（模拟网关异常崩溃）。
- **实测结果**：
  - TTL 未到期前（t=1015s），Janitor 巡检回收 0 条；
  - TTL 到期后（t=1035s），Janitor 巡检精准识别并回收 1 条孤儿预留，冻结金额清零，可用余额 100% 自动恢复。**PASS**。

### 对抗场景 4：客户端主动取消无损退还实测
- **测试**：`test_audit_b_cancellation_release_refund`
- **实测结果**：客户端点击停止，网关触发 `release()`，预留立即全额解冻，`credit_used` 维持 0，零资金损耗。**PASS**。

### 对抗场景 5：完整闭环与追加式账本校验
- **测试**：`test_billing_happy_path_reserve_settle_ledger`
- **实测结果**：预留 270,000 微积分 -> 真实 usage 结算 45,000 微积分 -> 差额自动释放 -> 账本写入且精准对齐。**PASS**。
