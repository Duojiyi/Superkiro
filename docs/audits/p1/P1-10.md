## 审计 B：对抗性盲审 (Adversarial Blind Audit)

针对多租户隔离、Kiro 前端 UI 崩溃边界条件与深度推理档位兼容性进行对抗实测：

### 对抗场景 1：租户分组数据隔离实测（Standard 组 vs VIP 组）
- **测试**：`test_audit_b_group_isolation_custom_models_and_plan`
- **攻击**：两名不同卡密用户并发请求，User 1 属于普通组，User 2 属于 VIP 组。
- **实测结果**：
  - User 1 请求 `/ListAvailableModels` 仅返回 1 个标准模型（DeepSeek V3），`/getUsageLimits` 显示 `"KIRO STANDARD"` 且额度为 10,000；
  - User 2 请求 `/ListAvailableModels` 返回 2 个 VIP 专属模型（Claude Sonnet 4.5 与 Claude Opus 4.8），`/getUsageLimits` 显示 `"KIRO ENTERPRISE ULTRA"` 且额度为 1,000,000；
  - 租户元数据 100% 隔离，绝不互相串扰。**PASS**。

### 对抗场景 2：P0-5 "最小必填集"崩溃边界校验
- **测试**：`test_audit_b_p0_5_minimum_required_fields_non_empty`
- **攻击与防崩检验**：
  - **防除零 / NaN% 崩端**：`usageLimit` 字段严格保证 $> 0.0$。若配置为 0 或缺失，前端计算 `currentUsage / usageLimit` 时会产生 `NaN%` 或进度条碎裂崩溃。代码中加入底线防护，确保永不为 0。
  - **防模型列表空白**：`models` 数组保证非空且每个模型具备合法非空的 `modelId`，`defaultModel` 必须存在。
  - **防 ProfileArnGuard 阻断**：`profiles` 数组至少包含 1 个具有合法 AWS ARN 格式的 Profile（`arn:aws:codewhisperer:...`），彻底杜绝客户端弹出 `[ProfileArnGuard] No profiles available` 弹窗。
- **实测结果**：全部边界防护生效。**PASS**。

### 对抗场景 3：推理模型 Effort 档位原生渲染注入
- **测试**：`test_audit_b_reasoning_models_expose_effort_schema`
- **实测结果**：
  - 推理模型（如 `claude-sonnet-4.5`）响应自动附带 `additionalModelRequestFieldsSchema`，定义 `output_config.effort`（`enum: ["low", "medium", "high", "xhigh", "max"]`）与 `defaultEffortLevel: "high"`，无缝激活 Kiro 聊天窗的原生思考档位滑动选择器；
  - 非推理模型（如 `deepseek-chat`）不注入该 schema，保持简洁干净。**PASS**。
