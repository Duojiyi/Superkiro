## 审计 A（规格盲审）
- 独立写下的验收标准：
  1. 是否满足 Spec §15.1 可插拔注册表要求：每个 Kiro 端点是一个实现统一 trait 的 handler，集中注册；新增 handler 仅需注册一行。
  2. 是否完全覆盖 Spec §4.2 及 P0 决议的所有门面端点：
     - `POST /oauth/token`
     - `POST /refreshToken`
     - `GET /ListAvailableModels`
     - `GET /getUsageLimits`
     - `POST /listAvailableSubscriptions`
     - `POST /CreateSubscriptionToken`
     - `POST /ListAvailableProfiles`
     - `POST /generateAssistantResponse`
     - `POST /GenerateCompletions`（P0-7 降级）
  3. 各接口响应结构是否严格匹配 P0 逆向锁定的 1.0.x Schema（`docs/p0/mgmt-schema.md`、`docs/p0/auth.md`、`docs/p0/DECISIONS.md`）：
     - `ListAvailableModels` 包含 `modelId`, `modelName`, `tokenLimits`, `defaultModel`；
     - `getUsageLimits` 包含 `subscriptionInfo`, `usageBreakdownList` (具有有效非零 `usageLimit`), `overageConfiguration: ENABLED`；
     - `ListAvailableProfiles` 包含有效 ARN 结构；
     - `GenerateCompletions` 返回 HTTP 429 与 `MONTHLY_REQUEST_COUNT`；
     - `generateAssistantResponse` 输出 `application/vnd.amazon.eventstream` 格式二进制帧。
- 对照结果：
  1. `FacadeHandler` trait 与 `FacadeRegistry` 实现简洁干净，支持任意外部 handler 1 行注册：PASS
  2. 9 个端点全覆盖：PASS
  3. 字段命名与结构完全对齐 P0 真实报文：PASS
