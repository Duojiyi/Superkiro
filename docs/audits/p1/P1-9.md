## 审计 B：对抗性盲审 (Adversarial Blind Audit)

基于实际网络异常、客户端中断和并发重放等极端对抗场景进行攻击测试验证：

### 对抗场景 1：上游首 Token 前超长等待（网络停顿 180ms，保活周期 50ms）
- **测试**：`test_stream_guard_keepalive_injection_during_idle`
- **预期**：在首 Token 产生前的静默期内，网关自动插入多条空的 `assistantResponseEvent` 保活帧，首 Token 到达后平滑输出文本，保持流不断开。
- **实测结果**：在 180ms 静默中精准截获并解码出 $\ge 2$ 条内容为空字符串的 `assistantResponseEvent` 帧，随后真实文本正常送达。**PASS**。

### 对抗场景 2：并发重放攻击（相同 `amz-sdk-invocation-id` 并发请求）
- **测试**：`test_audit_b_concurrent_replay_deduplication`
- **攻击**：同一客户端因为网络偶发卡顿，发出 2 个携带相同 `invocation_id` 的并发请求。
- **实测结果**：Attempt 1 成功拿到锁进入上游；Attempt 2 立即被拒绝 `IdempotencyError::InProgress`，杜绝重复转发与重复扣费。Attempt 1 提交完成后，后续请求重试直接返回 `IdempotencyError::AlreadyCompleted` 缓存短路。**PASS**。

### 对抗场景 3：客户端突发断开连接（中途取消，防费用与锁泄漏）
- **测试**：`test_audit_b_client_disconnect_cancellation_and_no_leak`
- **攻击**：客户端请求生成后，仅读取 1 个 chunk 便强制掐断 TCP 连接（模拟用户点击停止或网络中断）。
- **实测结果**：网关借由 `tx.closed()` 立即感知客户端 socket 断开，立即退出工作线程并销毁上游流；`IdempotencyGuard` 析构函数触发清理，`manager.is_in_progress(id)` 在数十毫秒内复位为 `false`，后续同 ID 重试可立即重新获取执行权，零锁残留，零上游泄漏。**PASS**。

### 对抗场景 4：上游突发 429 / 5xx 异常（友好错误体验）
- **测试**：`test_audit_b_mid_stream_provider_error_friendly_presentation`
- **实测结果**：不仅下发标准 AWS `InternalServerException` 异常帧，而且率先下发一条 Markdown 格式的友好错误文本 `assistantResponseEvent`（`⚠️ 上游模型服务异常: ...`），避免 Kiro IDE 界面静默黑屏。**PASS**。

### 对抗场景 5：工具调用名称还原与 Usage 精确计算
- **测试**：`test_stream_guard_normal_flow_with_tool_use_and_usage`
- **实测结果**：成功将超长工具名还原为原名，Prompt Caching 读取/写入 token 与非缓存 token 计算准确无误。**PASS**。
