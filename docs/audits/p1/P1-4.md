## 审计 A（规格盲审）
- 独立写下的验收标准：
  1. 编码器输出是否严格遵循 AWS EventStream 二进制协议格式：
     - 12 字节 prelude（`total_length`, `headers_length`, `prelude_crc`）
     - Header 块（名称长度 1B + 名称 + 类型 1B + 值长度 2B + 值）
     - Payload 块
     - 4 字节尾部 `message_crc`（针对前述全部字节的 CRC32）
  2. 是否提供所有 Spec §4.4 流式响应事件与异常的便捷编码函数：
     - `encode_assistant_response`
     - `encode_tool_use`
     - `encode_reasoning`
     - `encode_context_usage`
     - `encode_metadata`
     - `encode_keepalive`
     - `encode_exception`
  3. Keepalive 心跳包格式是否与 P0 逆向结论完全一致：
     - `:event-type: assistantResponseEvent`
     - `:content-type: application/json`
     - `:message-type: event`
     - payload: `{"content": ""}`（空内容，被 Kiro UI 忽略，但重置 60s/300s 看门狗）
  4. 是否对 P0 语料库实现字节级/无损语义级 round-trip 验证。
- 对照结果：
  1. Prelude 与 Message CRC 均采用与 P0 逆向完全相同的 ISO-HDLC IEEE 802.3 CRC32 算法，格式 100% 吻合：PASS
  2. 包含全部 7 个事件与异常助手函数：PASS
  3. `encode_keepalive()` 生成帧在解码后事件类型与 payload 结构与 P0 语料库完全对齐：PASS
  4. P0 语料库帧解码后再编码输出与原始字节 100% 逐字节完全匹配：PASS
