# 智能复杂度分流与服务端体验审计

日期：2026-10-02（Asia/Shanghai）
范围：服务端 Rust、后台管理界面、公共门户，以及关联客户端兼容、部署和回退关键路径。

## 独立性与结论

两名审查者分别开展只读审计，不读取既有审计报告或对方结果。各自提交结论后才合并发现并进行修复。审查期间实现仍在收尾，双方在结束前复读了关键源码；修复后的联合回归由实施方完成，不能把它当作第三次独立审计。

两份审计共同确认两项可用性问题。本次均已修复；没有据此宣称全项目零缺陷。功能默认关闭，发布不自动配置分类器、启用外部文本传输或产生分类费用。

## 发现与修复

| 编号 | 独立结论 | 问题与影响 | 修复及回归 |
| --- | --- | --- | --- |
| R1 | A/B：P1 | 策略复杂链任一成员停用时，保存决策仍验证整条原链，使健康备用无法接管；观察模式也可能返回 503。 | 保存前与当前模型、分组、能力筛选后的候选取有序交集；简单链和续接同样收窄。未外呼的空建议可记录，观察保持原链，执行不越权降级。真实请求测试覆盖两种模式的渠道停用、观察空建议和 PDF 能力交集。 |
| R2 | A：P2，B：P1 | 七天内共享记录达到 20000 条后，新增决策统一失败，日分类预算无法防止该容量条件。 | 满容量不驱逐未过期记录；停止新增分类与明细持久化，返回无外呼授权、无新增分类费用的合法路由结果。既有幂等记录仍优先命中。其他持久化失败不吞掉。后台显示容量和接近/达到上限提示。 |

补充收尾：全部策略关闭时允许失效的渠道/模型引用，确保紧急关停始终可发布；配置结构校验仍保留，再启用仍验证活跃引用。该问题在双方最终复读时已修复，因此不计入最终独立发现数。

主要实现和可执行证据：

- `crates/billing/src/complexity_routing.rs`：预算预占、持久化幂等、外呼 claim、容量降级、空建议及关停校验。
- `crates/gateway/src/complexity_routing.rs`：有限上下文、标签校验、超时熔断、合法候选交集和续接。
- `crates/gateway/src/facade/conversation.rs`：模板优先、能力筛选、真实回答渠道记录、原客户结算。
- `crates/billing/tests/complexity_routing_test.rs`、`crates/gateway/tests/complexity_routing_test.rs`、`crates/gateway/tests/complexity_conversation_test.rs`：容量、并发、重启、计费隔离和真实请求流水线回归。

## 用户体验

后台新增独立“智能分流”页，涵盖默认关闭、观察/执行模式、已有模型和渠道有序选择、精确费用输入、隐私确认、带费用确认的预览、实际服务渠道和预算/容量状态。冲突或不确定保存结果保留草稿并要求重新核对，禁止盲目重复提交；快速关停仅使用已保存配置，并保留普通编辑草稿。

运行参数页补齐拒绝/冲突后的草稿恢复、全局刷新保护、窄屏表格键盘可访问性。保留并验证已有响应模板的多代码/文案候选编辑能力。

门户完善空设备、加载、输入错误、非 JSON 响应、离开页面后的过期响应处理，以及手机导航和换机说明。使用本地夹具验证，不使用客户卡密。

## 回归结果

- `cargo fmt --all -- --check`、工作区 Clippy（所有目标，警告视为错误）：通过。
- billing 分流定向测试：27/27 通过；紧急关停另行复测通过。
- 新增 gateway 回归纳入全量测试：16 项分类/幂等/容量测试、8 项真实请求流水线测试。完整 Rust 工作区和 Linux/Windows CI 是发布阻断门槛，精确提交完成状态以 GitHub Checks 与发布回执为准。
- 后台 `npm test`、生产构建、登录/模板/运行参数/分流浏览器回归、体验/可用性/迭代/批量卡操作/发卡套件：通过；容量展示另行复测通过。
- 门户浏览器测试：29/29 通过；Pencil 对齐与 CSP 检查：5/5 通过；桌面/手机截图已抽查。
- 桌面 bridge/runtime 离线回归：24 项通过；部署离线回归：128 项通过。没有据此宣称未改客户端原生端到端已验收。

此前备份测试在高并发本地负载下出现过不同用例的 Git Bash 30 秒超时。最终按原超时和原 CI 命令复验：51 项执行，49 通过、2 项 Windows 不适用的 POSIX 检查跳过；原超时未复现。不以此次通过推断早前超时根因。

## 覆盖边界

两份审计均追踪了鉴权/管理员会话、计费预占与结算、持久化幂等、请求流和分类流、后台发布和门户敏感操作、桌面 IPC/更新/接管恢复，以及部署备份和回退关键路径。这是关键路径审查与抽查，不是每一行代码的完整证明。

未执行：真实分类模型质量/费用评估、生产负载压测、客户数据操作、Windows/macOS 原生安装恢复实测、未改客户端完整实机端到端、Safari/Firefox 或真实读屏器验证。已完成的本地浏览器检查使用 Chromium。

Vite 构建保留单个主 JS 包超过 500 kB 的提示，不影响构建成功；本次没有引入额外依赖或仅为消除警告重构打包。

## 发布与使用门槛

从 `origin/main` 单独提取本次服务端、网页和测试文档改动，不携带原工作分支未合并的客户端兼容/打包提交，不修改客户端发布清单。发布必须等待精确提交的 CI 通过，再执行既有候选构建、备份、账本加载核验、健康检查和失败回退流程。

上线验收只读核对：新分流 API 可用且默认关闭、未授权访问拒绝、门户静态文件和后台包更新、服务健康、镜像提交一致，以及原响应模板/运行参数/客户端下载清单哈希保持不变。发布的实际提交和验收结果由发布回执记录。

操作说明见 `docs/COMPLEXITY-ROUTING.md`。投入使用前，由管理员填写真实分类器渠道、模型、报价及预算，先用无敏感文本预览并观察，再按实测启用执行模式。
