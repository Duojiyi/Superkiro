## 审计 B：对抗性盲审 (Adversarial Blind Audit)

针对恶意重放、设备并发争抢、伪造指纹、撕裂写入及暴破渗透实施对抗性测试：

### 对抗场景 1：设备频繁换绑与冷却穿透攻击
- **攻击向量**：利用自动化脚本轮流上报伪造设备指纹，企图绕过单卡绑机限制。
- **实测检验**：
  - 首次登录绑定设备 1 成功；
  - 触发换绑至设备 2 成功，扣除 1 次换绑配额，`token_version` 自增至 2（使设备 1 即刻失效）；
  - 紧接着在冷却期内上报设备 3，网关立即返回 HTTP 429 `ThrottlingException: Device rebind cooldown active: ...s remaining`，拦截非法穿透；
  - 耗尽换绑次数后上报设备，直接返回 HTTP 403 `AccessDeniedException: Device rebind limit reached`。
- **实测结果**：**PASS**（见 `tests/auth_handshake_test.rs::test_rebind_eviction_and_cooldown_rejection`）。

### 对抗场景 2：`token_version` 即时吊销防御
- **攻击向量**：客户端持有先前签发的合法 `refresh_token`，在管理后台封禁或换绑后尝试静默续期。
- **实测检验**：
  - 卡密 `token_version` 递增或状态置为 `Banned`/`Frozen`；
  - 调用 `POST /refreshToken`，网关从内存比对最新版本号，立即返回 HTTP 401 `TokenRevokedException: Token version mismatch`，成功阻断任何僵尸续期。
- **实测结果**：**PASS**（见 `tests/auth_handshake_test.rs::test_token_refresh_and_instant_revocation_on_version_mismatch`）。

### 对抗场景 3：高频卡密枚举与字典攻击
- **攻击向量**：攻击者针对 `/oauth/token` 发起高频卡密碰撞探测。
- **实测检验**：
  - 注入 5 次不存在的卡密，前 5 次返回 HTTP 401 `UnrecognizedClientException`；
  - 第 6 次请求在网关安全层直接拦截，返回 HTTP 429 `LockoutException: Account locked due to consecutive failures: 900s remaining`，无数据库与卡密池穿透消耗。
- **实测结果**：**PASS**（见 `tests/auth_handshake_test.rs::test_login_brute_force_lockout`）。

### 对抗场景 4：文件系统撕裂与格式兼容性
- **攻击向量**：并发写入或磁盘慢速导致 Kiro 监听到半写 JSON。
- **实测检验**：
  - `TokenStorage::save` 强制使用 `.tmp.<pid>.<ts>` 写入并 `sync_all` 后原子 rename；
  - 测试套件验证 P0 官方报文双向序列化无缺失；
  - 过期时间检测对 RFC 3339 毫秒与秒级标准时间戳 100% 正确解析。
- **实测结果**：**PASS**（见 `patch-engine/tests/token_storage_test.rs`）。
