## 3. 执行摘要

### 已确认生效

- 网关启动必须提供 `AUTH_SECRET`、`ADMIN_KEY`/兼容字段 `ADMIN_SECRET` 和 `CARD_PLATFORM_KEY`；管理员密钥长度、缺失和与 `AUTH_SECRET` 冲突会阻止启动。

- Portal 的解绑和充值需要带 action、IP、TTL、一次性消费和 replay 防护的 challenge token；Portal 相关测试通过。
- 快照写入已采用临时文件、`sync_all()`、rename 和父目录同步；备份脚本已按当前 JSON 快照架构重写，并生成 checksum sidecar。

- `CardRateLimiter` 目前有实现和测试，但没有证据证明已接入真实 conversation 主链路。

## 6. 本轮新增修复确认

### Admin 路由边界

本轮已将 Admin 路由从 public router 中拆出，构建独立 `admin_router`，并在具体 handler 前统一执行 `admin_auth_middleware`。handler 内仍保留认证检查，形成纵深防御。该修复解决了“新增 Admin handler 可能误落公共路由”的结构性风险，但不等同于完成 session、RBAC、2FA 或 CSRF。

### 备份与恢复脚本

`deploy/backup/backup.sh` 和 `deploy/backup/restore.sh` 已按当前单机 JSON 快照架构重写：

- 备份拒绝不存在或空快照，并生成 `.sha256` sidecar。
- 恢复前验证 checksum 和 JSON 结构。
- 恢复采用临时文件和 rename；恢复前保留原快照副本。
- 脚本不负责 AEAD 解密、KEK 校验或防回滚；这些仍由网关启动和账务层承担。
