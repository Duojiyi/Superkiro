# BYOK V4 三端设计稿

日期：2026-09-19。范围：Pencil 设计与静态预览，不含产品代码落地、生产部署或端到端功能验收。

## 设计方向

- 桌面：独立登录 440×570，竖向主窗口 600×780，底部导航。登录只验证卡密；进入首页后手动启用连接。普通用户不接触网关 IP、上游 Key 或运维设置。
- 门户：暖白与松绿色。卡密验证后进入个人空间，集中管理余额、有效期、设备和充值；无虚构购买支付系统。
- 后台：浅色高信息密度工作台。九个功能区域分别处理资产、供应商、模型发布、审计与财务，不把后台缩成桌面客户端。
- 数字、状态、模型名均为演示。美元参考价、上游采购成本、实际收入、用户积分必须区分。

## 交互与实施边界

1. 桌面卡密验证成功应取得权益、有效期与余额，再进入首页。启用连接是独立的用户操作。
2. 连接状态必须区分配置应用、Kiro 是否运行、模型服务是否验证；不能以配置写入成功代替可用性成功。
3. 未找到 Kiro 时主动作变为选择安装位置。启用或恢复前提示保存工作；失败保留备份及明确的恢复路径。
4. 关闭窗口进入托盘不等于退出程序。退出时明确提供恢复并退出、留在托盘、取消。仅移除本产品安装的证书，不删除用户其他证书。
5. 内存自动监测与安全维护分开，不默认强制结束用户工作进程。图表展示范围、单位和采样时间。
6. 门户敏感动作需要安全验证。激活明确有效期开始时间；解绑明确授权影响和换绑次数；充值先核对目标及额度。结果未知先查询，禁止盲目重复提交。
7. 门户入口是现有卡密身份流程重排，不新增一个虚构的用户名密码账户体系。会话凭据不做浏览器持久保存。
8. 后台模型发现只生成草稿。发布需同时满足可用路由、Key 模型权限、分组权益和价格配置；保留并发版本校验与审计。
9. 定价界面使用“积分/百万 Tokens”的可读单位，实施时须严格换算现有微积分字段，并核对输入、输出、缓存等计费口径。
10. 无真实成本/收入数据时显示未配置，不计算虚构毛利。财务页面中的收入关联、结构化配置与差异预检是目标交互，需逐项对接后端。
11. 安全页的 TOTP、RLS 等为状态设计，不代表本次已检查生产部署。示例未启用/未验证也不是对真实服务器状态的断言。
12. 部分画板并列多个状态用于审阅，正式运行时按实际条件显示，不同时展示互相矛盾的卡密状态。

## 独立设计审阅后的修订

独立代理实际审阅了 8 张主稿，给出 3 项 P1 和 5 项 P2。已落实：

- 定价选中行、当前编辑模型、逐行配置入口与阻断项修复路径。
- 模型发现结果标明来源 Key，明确发现模型不等于授权调用。
- 新增 D02 发布差异/版本冲突状态，呈现分组、版本、旧价到新价、生效规则与审计动作。
- 概览图的小时刻度按真实柱位置对齐，增加每柱数值，并标注当前小时尚未结束。
- 后台核心表格压缩间距、提高操作文字到 14px。
- 桌面首页显示截断安装路径，提供明确“安装位置…”入口。
- 登录和门户统一“如何获取卡密”帮助入口。目标帮助说明须指向实际发卡渠道；本稿没有虚构购买页或客服地址，上线前需配置真实联系渠道。
- 门户区分卡密“有效”、设备“已绑定”和最近使用，已绑定用户不再看到误导性的首次连接提示。

第一轮布局检查已清除检测到的裁切。独立审阅不是严格研究意义上的双盲实验，也不等于全量可用性测试。

第二轮独立复看了定价、Key 和发布确认三张主稿；随后补齐具体价格生效时间及时区、发现操作的选中 Key、阻断修复按钮与操作列表头。最后一轮画布裁切检查无报告项。未宣称第三轮独立复审或运行时验收。
