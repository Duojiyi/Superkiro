## 1. 范围与分级

目标是现有管理员完成日常运营闭环，不要求新造企业管理平台。此次必须覆盖：登录及失效、卡密生成/交付/状态管理/调账、分组与模型价格发布、供应商与 Key、财务估算及导出、公告、桌面与窄屏操作。概览、追踪和配置审计作为核对入口，必须真实表达错误和数据口径。

| 等级 | 标准与例子 | 放行原则 |
| --- | --- | --- |
| P0 | 未授权读写；卡密/API Key 泄漏；越权或会话切换后泄漏旧秘密；重复入账、错扣款、破坏不可恢复账本；发布导致广泛错误计费 | 必须修复并复测，不接受带病放行 |
| P1 | 核心任务无法完成或产生错误对象/结果；发布覆盖并发版本；结果不明后误导重复写；已失败却显示成功；批量部分失败被掩盖；登录或窄屏阻断关键操作 | 本次支持范围内必须关闭；可以明确禁用受影响入口并重新验收可用替代路径，不能只写“已知问题” |
| P2 | 不改变权限、资金和最终结果，且有明确可操作替代路径的交互/文案/非敏感草稿损失 | 记录影响、替代路径与后续责任即可，不默认阻断 |

分级看实际影响，不按功能名称机械判断。证据缺口不是已确认漏洞，但 P0/P1 关键断言没有当轮证据时不可判定通过。普通未保存草稿丢失一般为 P2；若使管理员误发布旧配置、重复资金操作或无法恢复未确认意图，则升 P1/P0。

非目标：全量 RBAC、多租户审批、双人复核、完整 ERP/发票/收付款系统、供应商自动优选、定时公告平台、所有业务操作的统一批量 API、无限数据规模性能承诺、跨设备草稿同步。不能把这些扩展倒推为本次上线必需。
